Clase 10

Repetir y reutilizar: loops y funciones

En la Clase 9 nuestra lógica servía para un solo caso a la vez. Hoy aprendemos a repetirla sin copiar y pegar (loops) y a guardarla con nombre para usarla cuando queramos (funciones).

for

Cuando sabemos cuántas veces repetir.

for (let i = 0; i < 5; i++) {
  console.log(i);
}

while

Repite mientras la condición sea true.

let intentos = 0;
while (intentos < 3) {
  intentos++;
}

function

Código con nombre que recibe parámetros.

function saludar(nombre) {
  return "Hola, " + nombre + "!";
}

return

Entrega el resultado y termina la función.

saludar("Astrid");
// → "Hola, Astrid!"

Así cuenta un for (let i = 0; i < 5; i++)

i = 0 i = 1 i = 2 i = 3 i = 4 i = 5 → false, termina

Clase 11

Arrays, objetos y el DOM

Hoy ordenamos nuestros datos en arreglos y objetos, y JavaScript por fin se conecta con el HTML real de nuestra landing page a través del DOM.

Hoy trabajamos en otra página: abre index.html con Live Server y su consola (F12). El código de hoy está en script.js, el nuevo archivo de JavaScript de la landing page.

Arreglos

Una lista ordenada entre [ ]. El primer índice es 0.

const colores = ["rojo", "verde"];
colores.push("azul");
colores.length; // 3

Objetos

Datos relacionados en pares propiedad: valor entre { }.

const perfil = {
  nombre: "Astrid",
  nivel: "intermedio",
};
perfil.nombre; // "Luis"

querySelector

Devuelve el primer elemento que coincide con un selector CSS.

const titulo = document.querySelector("h1");
titulo.textContent; // "Mi Página Personal"

querySelectorAll

Devuelve todos los que coinciden, como una lista.

const enlaces = document.querySelectorAll("nav a");
enlaces.length; // 5

Clase 12

Modificar el DOM, eventos y formularios

En la Clase 11 JavaScript leyó nuestra página. Hoy la cambia, escucha lo que hace la persona que la visita y revisa el formulario antes de enviarlo.

Hoy los resultados se ven en la página: abre index.html con Live Server, prueba el botón 🌙 Modo oscuro, haz clic en tus intereses y envía el formulario vacío. El código está al final de script.js.

textContent / innerHTML

textContent cambia solo el texto. innerHTML interpreta etiquetas: úsalo con cuidado.

titulo.textContent = "Hola";
saludo.innerHTML = "<strong>Hola</strong>";

style

Cambia una propiedad CSS. Con guion en CSS → camelCase en JS.

badge.style.backgroundColor = "#1c6b5f";
// background-color → backgroundColor

classList

Agrega, quita o alterna clases que ya existen en styles.css. ¡La forma preferida!

li.classList.add("favorito");
li.classList.remove("favorito");
li.classList.toggle("favorito");

addEventListener

"Cuando pase esto, ejecuta esta función".

boton.addEventListener("click", function () {
  console.log("¡Clic!");
});

preventDefault

Evita que el formulario recargue la página al enviarse.

form.addEventListener("submit", function (event) {
  event.preventDefault();
});

value / includes

value es lo que se escribió en el campo. includes busca un texto dentro de otro.

// si escribieron "ana@mail.com":
correo.value.includes("@"); // true

¿Qué pasa cuando alguien hace clic?

  1. 1. La persona hace clic
  2. 2. El navegador avisa: "click"
  3. 3. addEventListener lo escucha
  4. 4. Se ejecuta la función
  5. 5. La página cambia

Clase 14

Git y GitHub: la historia de nuestros proyectos

Hasta hoy, la única forma de respaldar el proyecto era guardar el archivo. Con Git guardamos el historial completo de cambios en nuestra computadora, y con GitHub subimos una copia a internet.

Hoy trabajamos en la terminal: en VS Code, abre Terminal → Nueva terminal (o Ctrl + ñ). Asegúrate de que la terminal esté en la carpeta del proyecto, donde están index.html y la carpeta lista.

Repositorio

Una carpeta que Git está siguiendo. Se crea una sola vez con git init.

Staging area

La zona de espera: los cambios que irán en la próxima fotografía. Se llena con git add.

Commit

Una fotografía del proyecto con un mensaje que explica qué cambió. Se toma con git commit.

Push

Sube los commits a GitHub, la copia en internet. Se hace con git push.

Las tres zonas de Git

1 Working directory

Mis archivos tal como están ahora en la carpeta.

2 Staging area

Lo que elegí para la próxima fotografía.

3 Repositorio

El historial de fotografías (commits).

El camino de un cambio

  1. 1. Modifico un archivo
  2. 2. git add
  3. 3. git commit -m "…"
  4. 4. git push
  5. 5. ¡Aparece en GitHub!

Los comandos de hoy, en orden

$ git --version
$ git config --global user.name "Tu Nombre"
$ git config --global user.email "tucorreo@ejemplo.com"
$ git init
$ git status
$ git add .
$ git commit -m "Primer commit: landing page y lista de tareas"
$ git log --oneline
$ git remote add origin https://github.com/TU-USUARIO/TU-REPOSITORIO.git
$ git branch -M main
$ git push -u origin main

¿Cómo llega mi página al celular de otra persona?

  1. 1. Escribe la URL
  2. 2. El navegador pide la página
  3. 3. El servidor de Netlify la encuentra
  4. 4. Responde con HTML, CSS, JS e imágenes
  5. 5. ¡La página aparece!

Las partes de una dirección web (URL)

https://astrid-pagina-personal.netlify.app/lista/lista.html

https://

El protocolo. La s significa "seguro": la información viaja cifrada. Netlify lo da gratis.

astrid-pagina-personal

El nombre de mi sitio. Lo elijo yo en Netlify: minúsculas, números y guiones.

.netlify.app

El dominio de Netlify. Es como la "colonia" donde vive mi sitio, junto a miles de sitios más.

/lista/lista.html

La ruta: las mismas carpetas de mi proyecto. Por eso las rutas relativas funcionan igual.

Generador: ¿cómo se llamará mi sitio?

https://tu-sitio.netlify.app

Escribe arriba y mira cómo queda tu dirección.
